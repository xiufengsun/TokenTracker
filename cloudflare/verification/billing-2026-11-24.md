# Waffo sandbox payment verification

On 24 November 2026 the Cloudflare QA Worker created, settled and fully refunded one $4.99 test-mode monthly subscription for a dedicated QA account. The checkout used the Visa Success card provided by Waffo's sandbox cashier. All times below are UTC. The TokenTracker order fingerprint is the first sixteen hex digits of its SHA-256 hash, `0e9d4b3771ebc27a`.

| Check | Evidence |
| --- | --- |
| Checkout | At 04:38, calling checkout twice with the same request ID returned the same order and Waffo test session. The order was ready and unpaid. Its owner had free access and zero payment records. |
| Destination | At 04:46, querying the Waffo store after registration showed two sandbox HTTP destinations. The pre-existing destination and its event list matched the pre-change query. The new endpoint subscribed to twelve events at `api-qa-tokentracker-migration-staging.sunxiufeng1992.workers.dev/functions/tokentracker-waffo-webhook`. |
| Payment | At 04:49, payment and activation notifications had independently reached the QA Worker. The account reported one 499-cent payment and active membership with read and upload access. No client reconciliation call was needed to grant access. |
| Disable renewal | Reading the provider order returned `canceling` and `willRenew=false`. Reading TokenTracker returned `cancel_at_period_end=true` with the original paid-through date. |
| Full refund | The merchant sandbox API accepted one refund ticket. At 05:26 the Worker returned one 499-cent payment, 499 cents refunded, payment state `refunded`, membership `expired`, access source `none`, read access during the grace period and upload access disabled. The provider then independently returned one succeeded refund bound to the original test payment, store, local order and refund-ticket reference. |
| Delivery | Waffo delivery history for this order and the QA destination recorded HTTP 200 on attempt 1 for each of `subscription.activated`, `subscription.payment_succeeded`, `subscription.canceling` and `refund.succeeded`. |
| Replay | At 05:27, reconciling the same provider snapshot again preserved the single payment, refunded 499 cents and all membership fields. Duplicate and out-of-order signed event handling also ran in isolated workerd/D1 tests. |

The read-only production financial restore rehearsal used one PostgreSQL snapshot at 04:36. It restored all columns in fifteen financial tables into the D1 SQLite schema and compared all rows, including 65 orders, 12 payments, 17 subscriptions, 35 financial events and 9 gift grants. Foreign-key checks returned zero violations. D1 membership logic agreed with PostgreSQL for every returned field across 84 user/environment pairs at the same timestamp. The 65 source orders belonged to Waffo (61 live and 4 sandbox).

## Annual checkout and provider renewal

The dedicated QA owner paid $39.99 with the Waffo sandbox Visa success card. The provider assigned billing period 1 to the initial annual charge from 24 November 2026 08:32:14 UTC to 24 November 2027 08:32:14 UTC. The Worker recorded the same 3,999 cents, dates and active entitlement. Waffo's activation and first payment notifications each reached the QA endpoint on their first attempt with HTTP 200.

At 08:35 UTC the merchant's Test Mode subscription detail showed only the exact QA order matched by store, owner, product and order ID. One use of Waffo's **Simulate renewal success** generated a second distinct provider payment for 3,999 cents and billing period 2. Waffo delivered both the renewal and second payment notifications on their first attempt with HTTP 200. The next authenticated read found exactly two annual payments. The account expiry and provider period end were both 24 November 2027 08:35:59 UTC. Waffo's early simulation produced a 225-second second period contiguous with the first, as documented. This test used provider-driven callbacks without an application reconciliation request during acceptance.

After acceptance the dedicated test order was set to cancel at period end. Provider `willRenew` was false, the Worker retained both annual payments and the full paid-through date, and the cancellation notification also reached the QA URL on its first attempt. Settlement on a naturally occurring live annual renewal remains unverified.

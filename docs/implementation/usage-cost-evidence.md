# Usage cost evidence and coverage

## Reference and boundaries

Reference: [T3 Code](https://github.com/pingdotgg/t3code/tree/85aaef42d45681d3c02220a458464f1663a45bef), especially `packages/provider-grok/src/server/usage.ts`, `packages/provider-cursor/src/server/accountUsage.ts`, and `apps/server/src/usage/usagePricing.ts`. T3 consumes reported amounts; it does not supply an authoritative tariff for Cursor's opaque `grok-bot-*` products. No third-party empirical price mapping is introduced here.

This PR changes **derived local/cloud usage contracts** and existing UI disclosures. It does not deploy functions, change subscription billing, rewrite original logs, recompute production history, release a client, or claim to reconcile leaderboard totals.

## Amount contract (local coverage v1)

- Grok Build: `costUsdTicks` (and existing alternate spellings) / 10,000,000,000, otherwise explicit USD fields. Partial/incomplete reported amounts are not treated as complete. Input includes cache reads/writes; normalization subtracts them once. Reasoning is already part of provider output and becomes a disjoint local column.
- Cursor Grok Bot: the **existing CSV `Cost` field** is retained as a source-recorded export/paid amount, including explicit zero. Empty/invalid values remain missing. A supplied `tokenUsage.totalCents` is interpreted in cents, not ticks; this is supported by normalization, but **the existing CSV fetch does not magically acquire per-event cents**. No new private API or credential access is added. Source-recorded cost is not necessarily out-of-pocket billing or API-equivalent list price.
- `cost_coverage.version=1` stores the recorded sum, recorded/missing/allocated event counts, a fixed allowlist of field origins, and disjoint uncovered token columns. It never stores prompts, paths, gateway hosts, credentials, or raw source objects.
- Only uncovered tokens are estimated; unknown models remain unpriced, not free. Explicit recorded zero is not a missing-cost sentinel. Free Grok Build SKUs remain zero. Existing non-Bot Cursor API-equivalent estimates and Cline free/pass rules are unchanged.
- Grok Build model entries with missing costs may receive only the remaining trustworthy top-level turn amount, proportionally by token share. They are marked `grok_allocated`; allocation is not an official model rate. A parent total below the known child sum is not allocated. Queue and session scanners share this extraction. Free children do not dilute the paid-child allocation denominator. Parent partial/incomplete flags remain visible, and an unreadable v5-to-v6 migration input defers rebuilding without advancing the cursor or retracting prior usage.
- Local device-history transfers export `tokentracker.local-usage.v2` only when coverage is present, retain the allowlisted evidence through import, and still accept legacy v1 snapshots. Old clients reject v2 rather than silently reprice recorded zero/mixed amounts. Account-level Cursor exports remain excluded by the existing cross-device dedup policy.
- Grok cursor v6 and session sidecar v32 rebuild local derived snapshots on the next normal scan, without changing raw event files. No scan is executed against a user's home by opening this PR.

### Cloud coverage v1 and compatibility

The PR includes an **undeployed** PostgreSQL/InsForge migration, acknowledged upload protocol, and integration into all five account/leaderboard amount consumers. It does not claim old deployed servers or clients already support this contract.

- Nullable `cost_coverage` has a strict, bounded, private validator: allowed source/model, version, origins, event counts, USD equality and uncovered token subsets. No source object or sensitive path is accepted. The `NOT VALID` constraint does not scan/rewrite old rows but checks new writes.
- Narrow, transactionally guarded replacements extend the **installed** ingest, device-identity merger and archive-restore functions. Unexpected definition drift aborts the migration; unrelated fixes, OIDs and grants are retained. Existing archive payloads already serialize full hourly rows. No history backfill or rollup rebuild is run.
- A coverage batch first probes `cost_capabilities` without sending usage. The server acknowledges only after the versioned database wrapper successfully writes coverage. Unsupported servers, unsupported versions or missing acknowledgements retain the queue offset for retry. Legacy batches still use the old ingest path; legacy whole-row corrections clear stale coverage, rather than falsely keeping a zero/reported claim.
- The additive, admin-only `usage_cost_provenance_v1` side-wire leaves existing compact/token SQL formats and maintained leaderboard rollups unchanged. It carries reported USD, covered token vectors, allowlisted origins and reported/missing/allocated flags. It reads canonical hot/archive rows; machine-level Build and account-level Cursor retain their separate scope. Day filtering uses the caller's timezone and requested local-day range; all-time global reads retain eight UUID shards with at most two in flight.
- Each Edge consumer checks the side-wire's complete token basis against its existing token response **before** combining recorded USD with estimates of only uncovered, already-normalized input/cache/write/output/reasoning columns. Conflicting trustworthy canonical ties, missing/extra evidence or a stale rollup/cache inventory fail closed; retry or the existing rollup repair may be needed. No mixed-snapshot sum is published. Equivalent legacy positive Build USD and fully-covered metadata are not falsely treated as conflicts. Reliable cost wins an otherwise tied missing-amount candidate.
- Legacy positive Grok Build `total_cost_usd` keeps its existing reported meaning and gets an explicit legacy origin. Legacy zero is **not** retroactively called reported zero. Cursor Bot amounts require new provenance; an old number without provenance is not invented evidence. Opaque `grok-bot-*` products remain `cursor_subscription`/unpriced, including unknown suffixes. Free Build SKUs still cost zero.
- Summary/daily/profile/leaderboard totals use the same amount rule. Existing expanded model details receive reported/mixed/allocated/unpriced explanations and an independent allocation flag; no main-card marker is added. Legacy leaderboard field `estimated_cost_usd` retains its name for compatibility but can contain recorded USD plus uncovered-token estimates; it is not an invoice.

### Rollout gate (not performed)

This PR is not a deployment. Before any approved rollout, reconcile all changed Edge files with actual installed production definitions, including the five maintained price blocks; build the shared helper with the normal Edge bundler; validate the guarded migration against that baseline; then stage schema, ingest and consumers coherently and verify deployed hashes and isolated readback. The helper fails closed if a Grok/Bot consumer is installed without its RPC, and new coverage clients must not ship before the server acknowledgement exists. Existing old clients remain legacy: they cannot reconstruct source amounts or distinguish historical zero from missing. No public Bot tariff, absent log amount or completeness watermark can be manufactured by this schema.

## Four product improvements

1. **Coverage and scope:** local session response includes allowlisted scan inventory counts/states, actual check timestamp when available, latest observed event, requested range, pricing health, and local/cloud/leaderboard scope descriptions. Full completeness watermark, malformed-record coverage, cloud cutoff and leaderboard cutoff remain null/unknown. Discovered directories are not proof of zero usage; observed is not complete. No path or exception text is exposed by the new diagnostic shape. The scan-health payload and copy still state that this does not fix backend aggregation; that coverage disclosure is not shown on the dashboard or sessions UI.
2. **Unknown price refresh:** initialized pricing processes trigger a nonblocking single-flight catalog refresh on a miss, with a global 60-second cooldown. Failures retain current in-memory rates; invalid/empty catalogs do not replace them. Success increments revision, invalidates negative/model-info caches, and lets existing revision-keyed derived caches recompute estimates from unchanged token data. Curated precedence remains unchanged. No production auto-deployment is triggered.
3. **Alias ambiguity:** exact/source-curated/normalized aliases keep existing priority. Provider-qualified aliases use the actual vendor when known (`grok`→xAI, `codex`→OpenAI, `claude`→Anthropic); router/CLI names do not invent vendor identity. Conflicting candidate rates return unpriced/ambiguous instead of the alphabetically first reseller; identical rates remain usable. All Cursor `grok-bot-*` numeric lookups stay unpriced even if an upstream table guesses a rate.
4. **Calculation disclosure:** existing expanded model details explain recorded, model-estimated, unpriced, mixed and proportionally allocated amounts, including subscription meaning. No main-card symbol or `≥` is added. Expanded model explanations align with the model-name left edge. The coverage, cutoff and completeness disclosure is not rendered on the dashboard or sessions UI.

## Verification

Regression coverage includes explicit zero vs missing/invalid, mixed coverage, Grok top-level allocation, Cursor CSV ingestion→queue→local calculation, paid/export vs public-price semantics, free handling, vendor collision/exact precedence, catalog concurrency/cooldown/revision/failure, privacy allowlisting/unknown cutoffs, legacy/versioned upload compatibility, real queue→ingest handler→PostgreSQL→account HTTP responses plus all five calculators, archive/restore/device merging, canonical ties, stale-basis rejection, local-day range boundaries, and rendered disclosures. Production data and live functions are not verification fixtures.

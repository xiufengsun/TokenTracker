01

这个功能到底要做什么？

先用一个你每天都见的例子讲清楚需求，再给出三个端的"体检结论"。

科
新手科普：什么是"静默启动"？ 想想微信开机的样子：电脑开机后微信自动运行了，但你桌面上没有弹出聊天窗口——它只是安静地待在屏幕角落（任务栏托盘）里。等你有空点它，界面才弹出来。这种"启动后只留一个角落图标、不弹窗"的行为，就叫静默启动（silent start / 启动到托盘）。

对 TokenTracker 来说，需求就是一条用户故事：

User Story

“我开机登录后，TokenTracker 自己就上线了，但别抢我的屏幕。”

后台照常做三件事：① 本地服务器继续运行（:7680），② 继续解析 AI 日志、统计 token，③ 菜单栏/托盘图标待命。只有当我主动点击图标、或点了 tokentracker:// 链接时，主面板才出现。

三个端，三种"角落"

TokenTracker 有三个桌面客户端，"角落图标"在每家系统上的名字和机制都不一样——这是本调研所有复杂度的根源：

macOS · TokenTrackerBar

菜单栏 Menu Bar

屏幕右上角那排小图标。TokenTracker 是"菜单栏应用"（苹果叫 agent 应用：没有 Dock 图标、不抢焦点），点击图标弹出一个popover 小面板，另有完整仪表盘窗口。

技术：Swift + AppKit，面板是 NSWindow 里嵌 WKWebView。

Windows · TokenTrackerWin

系统托盘 System Tray

任务栏右下角时钟旁边。TokenTracker 常驻一个 NotifyIcon 托盘图标，左键点击弹出仪表盘窗口（WebView2 渲染网页），还养了一只桌面宠物。

技术：.NET 8 WinForms + WPF + WebView2。

Linux · TokenTrackerLinux

托盘托盘 Tray

取决于桌面环境（GNOME/KDE…），通常在顶栏。TokenTracker 用 Tauri v2（Rust 框架）构建，托盘只有右键菜单："Open Dashboard" 和 "Quit"。

技术：Tauri v2 + Rust + 内嵌 Node 服务器。

科
新手科普：为什么面板里都是"网页"？ 三个端的面板都是"原生窗口里嵌一个浏览器内核"：macOS 用 WKWebView，Windows 用 WebView2（微软 Edge 的内嵌版），Linux 的 Tauri 用 WebKitGTK。它们加载的都是同一套 React 仪表盘页面。所以"静默启动"还要回答一个问题：藏在后台时，这些网页容器会不会出幺蛾子？（剧透：不会，第 6 节有实验依据。）

三个端现状体检

最大的一份意外收获：三个端都已经有一部分静默启动的地基了，这个功能比想象中小。下表是逐项体检结果（✓ 已具备 · ⚠ 有缺口 · ✗ 没有）。

03

macOS 深潜：已经静默了，但用户不知道

TokenTrackerBar 的启动流程里已经埋好了一条"判断是否被系统拉起"的通道，只是没有暴露成设置。

关键代码：静默判断就藏在启动回调里

科
新手科普：什么是 "'lgit 小纸条"？ 当应用是通过"登录项"（开机自启）被 macOS 拉起来的，系统会随启动事件附赠一个名为 'lgit（launched as login item）的标记。应用读一下这个标记，就知道"我是被系统拉起来的，不是用户点的"。这是 Apple 官方文档里的机制（AERegistry.h 头文件原文："application was launched as a login item and probably shouldn't open up untitled documents"——连苹果都说：这种情况就别乱弹窗了）。

一个绕不开的平台限制

调查了一个"想当然"的方案：能不能在注册登录自启时顺手塞一个 --silent 命令行参数，像 Windows 那样？答案是不行。macOS 现代的登录项接口 SMAppService.mainApp.register() 不接受任何自定义参数，官方文档和社区维护者的回复都确认了这一点。所以 macOS 上想控制静默，只能把偏好存盘（UserDefaults），启动时读出来——幸运的是现有的 native:settings 桥接机制（网页设置页 ↔ 原生应用双向同步）已经万事俱备，加一个键就能用。

坑
已发现的隐患：自家检测写法与"社区验证版"不一致 我们用 attributeDescriptor(forKey: 'lgit) 直接读事件属性；而被广泛验证的开源库 LaunchAtLogin-Modern 用的是 paramDescriptor(forKey: keyAEPropData).enumCodeValue == 'lgit。两者目标相同，但解析路径不同。若未来某个 macOS 版本上静默失效，第一件事就是对齐这个写法。另外这个小纸条只在 applicationDidFinishLaunching 里读得到，过后就没了——现有代码的位置刚好正确，重构时别挪。

Windows 深潜：万事俱备，只欠"宠物让路"

Windows 端的静默启动框架已经完整落地——注册表自启带参数、单实例互斥、关窗收托盘都有了。唯一的漏洞出在桌面宠物身上。

新手科普：?? 是什么意思？ a ?? b 读作"a 如果不是空就用 a，否则用 b"。这行的意思是"优先用存档的宠物偏好；没存过才看启动类型"。逻辑本身没错，错在优先级：静默启动这种"系统级指令"应该压过界面偏好，而不是反过来。
重点
WebView2 在后台会不会罢工？（做了专项调研） 不会，但有三个细节值得知道：① 初始化绑定在窗口的 Loaded 事件上——窗口不显示就不初始化，静默启动反而省了内存，首次打开才加载（代价可接受）；② 一旦显示过后再藏起来，页面 JS 照常跑（项目已加 --disable-background-timer-throttling 等参数对抗节流）；③ 隐藏时网页不渲染、定时器会被 Chromium 降速（100ms → 1s），这是微软文档明说的行为，不是 bug。微软官方甚至"鼓励"把隐藏窗口的 WebView 关掉渲染省资源。
05

Linux 深潜：一张白纸，但底子最好

Linux 端（Tauri v2 + Rust）目前完全没有静默启动：窗口 100% 弹出，也没有登录自启功能。但它的架构让改造变得非常便宜。

科
新手科普：Tauri 和那几个新名词 Tauri 是一个用 Rust 写桌面应用的框架（对标 Electron，更省内存）。窗口由 Rust 代码创建。autostart 插件是官方维护的"登录自启"组件：开启后，Linux 上它会往 ~/.config/autostart/ 写一个 .desktop 文件——你可以把它理解成"Linux 桌面的开机自启名单"，名单里 Exec= 那一行写什么命令，登录后就执行什么命令。参数可以随便带，这正是我们需要的通道。

现状：窗口创建时没有"隐藏"选项

autostart 插件在各平台到底写了什么（读了源码验证）

平台写入位置能带 --hidden 参数吗
Linux~/.config/autostart/xxx.desktop，参数原样进 Exec= 行✓ 可以（AppImage 也能自定位路径）
WindowsHKCU\...\Run 注册表 + 一个"已启用"标记✓ 可以
macOS~/Library/LaunchAgents/xxx.plist✓ 可以，但 我们不用它——已有更正宗的 SMAppService
坑
Linux 特有的三个坑，实现时必须盯住 ① GNOME 默认不显示托盘图标——用户得装 gnome-shell-extension-appindicator 扩展，否则图标干脆不出现（不报错，纯隐形）；② Wayland 下 hide→show 往返有已知 bug（tao#1299）：窗口标题栏按钮可能失灵，需要真机手测；③ AppImage 更新后路径会变——.desktop 里写的是绝对路径，应用更新后要重新 enable 一次自启。
06

四个关键发现

如果只带走四条结论，是这四条。每条都查证过官方文档或源码，附录有出处。

发现 1 · macOS

SMAppService 传不了参数，静默只能靠"存档"

macOS 登录项 API 不接受自定义命令行参数（官方文档 + 库作者双重确认）。但系统会塞 'lgit 小纸条，且我们的代码已经在正确位置读取它。结论：偏好存 UserDefaults，启动时读，桥接设施现成。

发现 2 · Windows

带参数自启是微软认可的正路

微软文档明说 Run 键的值"就是一条命令行"，且系统会刻意延迟自启程序执行、避免干扰前台——"自启就该安分"是平台共识。我们的 --startup 暗号已经就位，唯一的坑是宠物偏好优先级。

发现 3 · 全平台

网页面板藏后台都不出事

macOS 的 WKWebView 本来就是显示时才创建（静默 = 零开销）；Windows 的 WebView2 不显示就不初始化，显示过后隐藏也能跑 JS；Linux 的 wry 引擎在窗口隐藏时照样加载 URL——首次打开就是热的。三家的官方文档都支持"隐藏运行"这种用法。

发现 4 · 架构

"静默"只是 UI 表层，后端完全无感

三个端的服务器生命周期都与窗口可见性解耦：macOS 的 ServerManager、Windows 的后台同步、Linux 的健康监控线程，全部照常工作。所以静默启动不需要动任何数据链路代码，只动"启动时显示什么"这一层。

07

推荐方案

一份三个端统一遵守的"行为契约"，加上每端一小节改动清单。实现前请先拍板第 8 节的四个问题。

行为契约（三端统一）

场景主面板 / 宠物理由
登录自启（登录项 / Run 键 / .desktop）✓ 全部安静，只有角落图标平台共识：系统拉起的程序不该打扰用户
手动启动（双击图标）维持各端现状（macOS 弹面板；Windows 按宠物偏好；Linux 弹窗口）用户主动动作，给反馈是应该的
用户点击图标弹出面板（永远有效）这是面板出现的主通道
深链 / OAuth 回调弹出面板（永远有效）登录流程需要界面配合，不能吞
偏好开关"启动时打开面板"默认关；打开后自启也弹面板给想要"开机即见"的用户留出口

每端改动清单

macOS · 预计 1 个 PR

加开关，别动判断位置

① 新增 UserDefaults 键（如 LaunchSilently），扩展现有 if 条件（TokenTrackerBarApp.swift:149）；② 三处 UI 同步：菜单栏菜单项、NativeBridge.pushSettings 载荷 + applySetting 分支、网页设置页 MenuBarSection.jsx——全部照抄 launchAtLogin 的现成模式。

Windows · 最小改动

一行优先级 + 一个托盘勾选

① 让 --startup（或新增 StartSilently 存档）压过 PetWindow.StoredVisible（TrayApplicationContext.cs:242）；② 托盘菜单在"Launch at Login"旁边加一个"Start silently"勾选项，存进 native-settings.json（写法照抄 PetWindow.WriteSettings）。仪表盘不用动。

Linux · 新增两件套

--hidden 参数 + autostart 插件

① main.rs 解析 --hidden（与 Windows 的 --startup 命名统一），有则给窗口构建器加 .visible(false)；② 引入 tauri-plugin-autostart，注册时传 ["--hidden"]，托盘菜单加"Launch at Login"；③ 单实例回调：第二次启动若无 --hidden 就 show 窗口（现状已是如此，补个判断即可）。

重点
工作量评估 三端合计是"小到中型"改动：macOS 和 Windows 各自一天内可完成（模式全部现成），Linux 稍多（新增插件 + 测试），因为要覆盖 AppImage / deb / rpm 三种包形态的验证。真正的成本在跨三个桌面环境的手工测试（尤其 Wayland）。
08

实现前需要拍板的 4 个问题

这些是产品决策，不是技术问题——技术方案已经齐备，拍板后即可动工。

Q1

手动启动也要静默吗？

现状：macOS 手动双击会弹面板（代码注释里写明是有意设计）。建议：保持"手动 = 显示"，只让自启静默。想要全静默的用户可以用偏好开关自己关。

Q2

Windows 的桌面宠物算不算"打扰"？

宠物是氛围挂件，不是信息面板——有观点认为它可以在自启时照常出现。建议：--startup 压制一切（含宠物），"静默 = 什么都不弹"心智最简单。

Q3

"登录自启"是否默认隐含"静默"？

建议：是。自启默认安静；偏好开关的存在意义是允许用户"退出静默"（即"自启时也打开面板"），而不是默认打扰、让用户去关。这符合两家平台的官方倾向。

Q4

Linux 是静默 + 自启一起上，还是分步？

静默参数本身几乎零成本，但"登录自启"对 Linux 端是全新能力（新插件 + 三种包形态验证 + AppImage 路径过期问题）。可以一起发，也可以先发静默参数、自启下一版跟上。

09

新手术语表

按出场顺序整理，看报告时随查随用。

菜单栏应用 Menu Bar App
macOS 上的应用类型（官方叫 agent app）：没有 Dock 图标，只在屏幕右上角菜单栏挂一个小图标。由 Info.plist 里的 LSUIElement=YES 声明。TokenTrackerBar 就是这种。
系统托盘 System Tray
Windows 任务栏右下角、Linux 顶栏角落的小图标区。常驻后台应用的"灯牌"。
登录项 / 自启 Login Item / Autostart
用户登录系统后自动运行某程序的机制。三平台各有一套：macOS 用 SMAppService，Windows 用注册表 Run 键，Linux 用 autostart 目录下的 .desktop 文件。
SMAppService
Apple 官方的登录项管理接口（macOS 13+）。一行 register() 完成登记，但不能附带自定义启动参数——本调研的关键约束之一。
'lgit 标记
macOS 塞给登录自启应用的"小纸条"（Apple 事件属性），告诉它"你是系统拉起来的"。代码里用 keyAELaunchedAsLogInItem 常量读取。只在启动回调里能读到。
NSPopover / NSWindow
AppKit 的界面元素：popover 是贴着锚点的小浮层（菜单栏点击弹出的小面板），window 是完整窗口（TokenTracker 的仪表盘）。NSPanel 是特殊窗口（桌面宠物、灵动岛用的）。
WKWebView / WebView2 / WebKitGTK
三家平台的"内嵌浏览器"：macOS、Windows、Linux 各自的原生网页容器，TokenTracker 的仪表盘网页就跑在里面。
ApplicationContext
WinForms 的"无主窗口"程序骨架：程序不必依赖一个窗体存活，适合托盘常驻应用。TokenTrackerWin 的架构核心。
NotifyIcon
WinForms 的托盘图标组件，支持左键点击、右键菜单（打开面板/退出等）。
注册表 Run 键
Windows 登录自启名单：HKCU\Software\Microsoft\Windows\CurrentVersion\Run。键值就是一条完整命令行，天然支持带参数。
Message-基于单实例
"同一程序只允许跑一份"的机制。TokenTracker 用系统级互斥锁（mutex）实现；第二次启动会把消息转发给第一个实例然后自己退出。
深链 tokentracker://
类似网页链接的自定义协议。点它（比如 OAuth 登录回调）会唤起已安装的应用——静默启动时必须保证深链仍能弹出面板。
Tauri
Rust 写的跨平台桌面框架，窗口由 Rust 创建、页面用系统浏览器内核渲染。TokenTrackerLinux 用它打包出 AppImage / .deb / .rpm。
.desktop 文件
Linux 桌面的"程序名片"：名字、图标、启动命令（Exec）都写在里面。放进 ~/.config/autostart/ 就成为登录自启条目。
Wayland / X11
Linux 的两代窗口显示协议。Wayland 下有一些历史遗留的窗口管理怪癖（如 hide→show 后标题栏按钮失灵），实现时需手测。
AppImage / .deb / .rpm
Linux 三种主流分发格式：单文件绿色版 / Debian 系安装包 / RedHat 系安装包。TokenTracker 三种都发。
